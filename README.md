# 短信转发（荣耀 / Android）

收到短信后**自动转发**到企业微信 / 钉钉群机器人、**另一个手机号**或**邮箱**，还能按白名单**自动回复**。
支持号码与关键词过滤。纯 Kotlin 编写，无第三方网络库（邮件也是手写的 SMTP 客户端），
静态注册短信广播，**不需要常驻前台服务**。

---

## 一、它能做什么

| 能力 | 说明 |
| --- | --- |
| 自动转发 | 收到短信后几秒内送出，长短信自动合并为一条 |
| 四种渠道 | 企业微信、钉钉（含加签）、**短信（转发到另一个手机号）**、**邮箱（SMTP 发信）** |
| 邮箱关联 | 选服务商自动带出服务器参数，点「关联账号」当场验证登录，界面显示关联状态 |
| 测试账号 | 一键向 Ethereal 申请随机 SMTP 测试账号并自动填表，没有邮箱也能先验证通道 |
| 设置板块 | 首页右上角「设置」：集中检查 6 项权限状态，并可检查 / 下载 / 安装新版本 |
| 自动回复 | **不同号码回不同内容**（每行「号码 = 回复内容」），带防死循环保护 |
| 消息模板 | 自定义文案，支持 `{sender}` `{content}` `{time}` `{code}` `{device}` 变量 |
| 号码过滤 | 不过滤 / 白名单 / 黑名单，支持普通文本与正则 |
| 关键词过滤 | 不过滤 / 白名单 / 黑名单，例如只转发含「验证码」的短信 |
| @ 提醒 | 钉钉、企业微信可 @ 指定手机号或 @所有人 |
| 失败重试 | 网络抖动时自动重试一次（广播接收器内控制总耗时，不会 ANR） |
| 转发日志 | App 内保留最近 50 条记录，成功/失败一目了然 |
| 一键测试 | 无需真发短信，直接向机器人或目标号码发测试消息验证配置 |

**边界说明**

- 本应用**不会拦截、删除或修改**你的短信，只是在收到后额外送出一份。
- 「转发到另一个手机号」和「自动回复」依赖 `SEND_SMS` 权限。只要用户授予该权限，
  普通应用用 `SmsManager` 就能直接发送，**不需要**成为系统默认短信应用，也不会每次弹确认框。
  （网上常说“普通应用发不了短信”，那指的是没有申请 `SEND_SMS` 的情况。）
- 发短信按运营商资费计费，请自行确认套餐。本应用只在收到短信时被动发送，不会主动群发。
- 自动回复**只对白名单号码生效**，且不会回复以「【自动回复】」开头的内容，
  避免两台装了本应用的手机互相回复刷爆话费。
- 本应用**不申请无障碍、悬浮窗等敏感权限**，也不需要 root。

## 二、快速开始（3 步）

### 1. 准备转发目标

**方式一：群机器人**

**企业微信**：群聊 → 右上角 `…` → 群机器人 → 添加机器人 → 复制 Webhook 地址
形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx`

**钉钉**：群设置 → 智能群助手 → 添加机器人 → 自定义 → 安全设置勾选「加签」→ 复制 Webhook 与加签密钥
形如 `https://oapi.dingtalk.com/robot/send?access_token=xxxxxxxx`
（若安全设置选的是「自定义关键词」，则加签密钥留空，但关键词必须能出现在短信里）

**方式二：另一个手机号**

不需要任何外部配置，在 App 里把渠道选成「短信」，填上目标手机号即可。
适合「把备用机收到的验证码转到随身机」这类场景，代价是按条计费。
注意首次使用需要在首页授予**短信发送权限**；华为 / 荣耀机型**还必须授予「电话」权限**，
否则会报 `getGroupIdLevel1`（详见第六节）。

**方式三：邮箱**

不需要申请任何开发者账号，用你已有的邮箱即可，适合长期归档、不依赖任何 IM。
流程：渠道选「邮箱」→ 选**服务商**（QQ / 163 / 腾讯企业邮箱 / Gmail / Outlook，服务器参数自动带出）
→ 填账号和**授权码**（不是登录密码）→ 点 **「关联账号」**。
关联成功后会显示 `✅ 已关联发件邮箱：xxx@qq.com`，之后才允许转发。详见第四节「邮箱渠道」。

### 2. 构建并安装

见下方「三、构建」。

### 3. 在手机上配置

1. 打开 App → 打开**转发开关** → 按提示授予**短信收发权限**与**通知权限**
2. 点**关闭电池优化** → 允许
3. 点**配置转发目标与过滤** → 选渠道 → 按提示填目标（Webhook / 手机号 / SMTP 配置）
   →（钉钉填加签密钥）→ 需要的话再开**自动回复** → **保存并测试**
4. 接收端（群、另一台手机或邮箱）收到测试消息即配置成功
5. **务必**再按「五、荣耀 MagicOS 保活设置」逐项设置一遍

## 四、配置详解

### 过滤规则

规则**每行一条**，两种写法：

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| 普通文本 | 忽略大小写的「包含」匹配 | `95533`、`验证码`、`工资到账` |
| `re:` 开头 | 正则匹配 | `re:^106`、`re:(验证码\|校验码)` |
| `#` 开头 | 注释，忽略 | `# 银行短信` |

号码匹配会自动忽略 `+86` 前缀，因此规则 `13800138000` 能命中 `+8613800138000`。

- **白名单**：只有命中的短信才转发
- **黑名单**：命中的短信不转发
- 号码与关键词是**与**关系：两者都通过才会转发

**典型用法**

```
只转发银行的：
  号码白名单：95533 / 95588 / re:^106

只转发验证码：
  关键词白名单：验证码、校验码、动态码

不转发垃圾营销：
  关键词黑名单：退订、优惠、促销
```

### 消息模板

默认模板：

```
【短信转发】
发件人：{sender}
时间：{time}
内容：{content}
```

| 变量 | 含义 |
| --- | --- |
| `{sender}` | 发件号码 |
| `{content}` | 短信正文 |
| `{time}` | 接收时间 `yyyy-MM-dd HH:mm:ss` |
| `{code}` | 自动提取的验证码，提取不到时为空 |
| `{device}` | 手机型号 |

钉钉安全设置若为「自定义关键词」，请确保模板里包含该关键词（默认模板含「短信转发」）。
企业微信若要用 `@all`，请用界面上的「@所有人」开关，直接在手机号框里填 `@all` 无效。

### 自动回复（不同号码回不同内容）

需在首页授予**短信发送权限**。开启后，只有同时满足以下条件的短信才会被自动回复：

1. 通过上面的号码 / 关键词过滤；
2. 发件号码命中下面配置的**某条自动回复规则**（规则为空则完全不回复）；
3. 短信内容不以「【自动回复】」开头（防死循环）。

规则**每行一条**，格式为「号码 = 回复内容」：

```
# 老婆：专属回复
13800138000 = 【自动回复】老婆我在开会，稍后回你

# 银行 / 服务号：统一回复
re:^106 = 【自动回复】您的短信已收到，请勿回复本条

# 老爸：不写内容，用设置页里的「默认回复内容」
13900139000
```

- 等号左边是**号码规则**，写法与上面的过滤规则完全一致（包含匹配，或 `re:` 正则）；
- 等号右边是**该号码专属**的回复内容；
- **省略「= 回复内容」**的行，会使用设置页里的「默认回复内容」；
- 用**第一个等号**切分，所以回复内容里可以包含等号（`13800138000 = 验证码=已收到` 也能正确解析）；
- 规则**按书写顺序**匹配，第一条命中的生效 —— 所以把更精确的号码写在前面。

回复内容同样支持 `{sender}` `{content}` `{time}` `{device}` 变量。

**请保留开头的「【自动回复】」** —— 它既是给人看的标记，也是防止两台手机无限互回、
刷爆话费的唯一判据。

默认回复内容：

```
【自动回复】您的短信已收到，我会尽快回复。
```

> **兼容旧配置**：以前只填号码的写法可以原样继续用，那些行会被当作「使用默认回复内容」。

### 短信渠道（转发到另一个手机号）

1. 渠道选「短信」，在「目标手机号」里填接收号码，多个号码用逗号或换行分隔；
2. 在首页授予**短信发送权限**；
3. 保存并测试。

超过 70 字的短信会按运营商规则自动分段发送（`SmsManager.divideMessage`），
接收方看到的仍是一条完整短信。费用按运营商短信资费计，由本机承担。

**华为 / 荣耀 / 鸿蒙机型必读**：这些 ROM 的 `SmsManager` 实现内部会调用 `getGroupIdLevel1()`，
该接口要求 `READ_PHONE_STATE`（系统里显示为**「电话」权限**）。缺少它时发送会直接失败，
而报错信息里只有一行 `getGroupIdLevel1`，完全看不出跟权限有关。本应用已内置该权限的申请；
若你看到这条报错，去 `设置 → 应用 → 应用管理 → 短信转发 → 权限 → 电话` 设为允许即可。

### 邮箱渠道（关联发件账号）

**没有可用邮箱？先点「生成测试账号」。** 它会向 [Ethereal Email](https://ethereal.email) 申请一个
随机 SMTP 账号并自动填好所有字段，不需要注册、免费，几秒就能拿到。
**但它不会把邮件真正投递出去** —— 邮件会被截获在 ethereal.email 网站上，需要登录该网站才能看到。
所以它只适合验证「配置能不能发出去」；确认通道没问题后，记得换回你自己的邮箱。

> **如果你用测试账号看到「已转发到邮箱」但收件箱里没有 —— 这是正常的，不是 bug。**
> Ethereal 只负责接下邮件，不会转发给收件人。换用自己的邮箱才会真正投递。

配置流程就三步：

1. 渠道选「邮箱」→ **选服务商**（QQ 邮箱 / 163 邮箱 / 腾讯企业邮箱 / Gmail / Outlook / 自定义）。
   选完服务器地址、端口、SSL 自动填好，只有选「自定义」时才需要手填。
2. 填**邮箱账号**和**授权码**（密码栏下方会提示该服务商该填什么）。
3. 点 **「关联账号」**。

点下去会真的连一次 SMTP 服务器做登录验证（**只登录，不发信**）：

- 成功 → 按钮下方显示 `✅ 已关联发件邮箱：xxx@qq.com`，并出现「解除关联」按钮；
- 失败 → 直接显示原因，例如 535 会告诉你去生成授权码、超时会提醒你检查端口与 SSL 是否配套。

**没关联成功就不允许转发**，免得等到真收到短信才发现配置是错的。

几个细节：

- 改了服务器 / 端口 / SSL / 账号 / 密码中任意一项，「已关联」状态会自动作废，需要重新关联；
- 「解除关联」会清空已保存的密码；
- 收件人可以在关联之后再填，关联本身不需要收件人。

**最重要的一条：填授权码，不是登录密码。** 国内邮箱基本都禁止第三方用登录密码发信，
用密码会稳定报 `535 认证失败`。

| 邮箱 | SMTP 服务器 | 端口 | 使用 SSL | 密码栏填什么 |
| --- | --- | --- | --- | --- |
| QQ 邮箱 | `smtp.qq.com` | 465 | ✅ | 设置 → 账户 → POP3/SMTP服务 生成的**授权码** |
| 163 邮箱 | `smtp.163.com` | 465 | ✅ | 设置 → POP3/SMTP/IMAP 开启后获取的**授权码** |
| 腾讯企业邮箱 | `smtp.exmail.qq.com` | 465 | ✅ | 邮箱登录密码或客户端专用密码 |
| Gmail | `smtp.gmail.com` | 465 | ✅ | 开启两步验证后生成的**应用专用密码** |
| Outlook | `smtp.office365.com` | 587 | ❌ | 账户密码或应用密码 |

补充说明：

- 邮件主题用模板渲染，默认 `【短信转发】{sender}`，支持 `{sender}` 与 `{time}`；
- 邮件正文就是上面「消息模板」渲染出的内容，UTF-8 编码，中文不会乱码；
- 底层是本工程手写的 SMTP 客户端（`channel/SmtpClient.kt`），
  支持 SSL 直连、STARTTLS 与 AUTH LOGIN，**没有引入 JavaMail 等任何第三方库**。

## 五、荣耀 MagicOS 保活设置（重要）

荣耀 MagicOS 的后台管控较激进，**只授予短信权限是不够的**，
必须同时完成下面 4 项，否则锁屏一段时间后可能收不到短信或转发失败。

### 1. 应用启动管理（最关键）

`设置` → `应用` → `应用启动管理` → 找到「短信转发」→ **关闭「自动管理」** → 手动全部打开：

- ✅ 允许自启动
- ✅ 允许关联启动
- ✅ 允许后台活动

### 2. 电池优化白名单

App 首页点**「关闭电池优化」**按钮 → 选择「允许」。

手动路径：`设置` → `应用` → `特殊访问权限` → `电池优化` → 所有应用 → 「短信转发」→ 不允许优化。

### 3. 通知权限

`设置` → `通知和状态栏` → `短信转发` → 允许通知。
（通知不仅是提醒，也是判断 App 是否被系统冻结的信号。）

### 4. 后台锁定

打开最近任务（多任务）界面 → 找到「短信转发」卡片 → **下拉卡片** → 点出现的**锁形图标**。

### 补充建议

- `设置` → `电池` → `更多电池设置` → 打开**「休眠时始终保持网络连接」**
- `设置` → `移动网络` → `流量管理` → `应用联网` → 确保「短信转发」的**移动数据**与 **WLAN** 都已勾选
- 不要开启「超级省电模式」
- 首次配置完成后，重启一次手机验证：开机后应收到「短信转发已就绪」通知

### 验证是否真的生效

1. 锁屏，用另一台手机给本机发一条短信
2. 10 秒内群里应出现转发消息
3. 若没出现：打开 App 看「最近记录」——
   - 有记录但显示失败 → 网络或 Webhook 配置问题，看失败原因
   - 完全没有记录 → 说明广播没收到，回到第 1、2 项检查保活设置

## 六、设置板块

首页右上角「设置」进入，分两个板块。

### 权限检查

六项逐条列出状态，缺哪项就显示「去开启」，点一下直达对应系统页面：

| 项目 | 为什么需要 |
| --- | --- |
| 短信接收权限 | **必需**，没有它收不到任何短信 |
| 短信发送权限 | 短信渠道与自动回复需要 |
| 电话权限 | 华为 / 荣耀 / 鸿蒙机型发短信必需，否则报 `getGroupIdLevel1` |
| 通知权限 | 可选，用于查看转发结果与「已就绪」状态 |
| 电池优化 | 建议关闭，否则锁屏久了会被系统冻结 |
| 安装未知应用 | 仅在本页安装新版本时需要 |
| 验证码安全保护 / 通知信息整合 | **不是 Android 权限**，而是系统短信 App 的开关，见下方说明 |

底部「一键申请所需权限」会一次性发起所有运行时权限申请；
从系统页面返回时会自动重新检查，不用手动刷新。

> **关于最后一项**：华为 / 荣耀 / 鸿蒙机型的「信息」App 里有两个开关 ——
> **验证码安全保护** 与 **通知信息整合**。开启时，系统**不会把含验证码的短信广播给第三方应用**，
> 这类短信我们连收都收不到，转发日志里也不会有任何记录。
> 典型症状就是「普通短信能转发，验证码短信转发不了」。
>
> 它不是 Android 权限，第三方应用读不到状态，所以这一项显示为「需手动确认」；
> 点「去检查」会尽量跳到短信设置页，并弹出关闭步骤。

### 版本与更新

- 顶部显示当前版本号（形如 `1.0.0 (1)`）；
- 填一个**更新信息地址**（JSON），点「检查更新」；
- 有可用版本时列出**所有历史版本**，每条显示版本号、更新说明与「下载并安装」；
- 当前版本标注「当前版本」且不显示安装按钮，更高版本标「可更新」，更低版本标「旧版本」。

**更新信息 JSON 格式**（模板见 `dist/update.json`）：

```json
{
  "versions": [
    {
      "versionCode": 2,
      "versionName": "1.1.0",
      "url": "https://your-server.example.com/smsforwarder-1.1.0.apk",
      "changelog": "1. 新增设置板块\n2. 修复 xxx"
    },
    {
      "versionCode": 1,
      "versionName": "1.0.0",
      "url": "https://your-server.example.com/smsforwarder-1.0.0.apk",
      "changelog": "首个版本"
    }
  ]
}
```

- `versionCode` 必须**大于**当前版本才会标为「可更新」；
- `url` 必须是 APK **直链**（点开就能下载，不是网页）；
- 顶层直接写单个版本对象也可以，会被当作只有一个版本；
- 这个地址由你自己提供（服务器、对象存储、局域网都行）—— 本应用不依赖任何中心服务器。

下载的 APK 存放在应用私有目录（`getExternalFilesDir/apk/`），通过 `FileProvider` 交给系统安装程序，
**不需要任何存储权限**。首次安装会要求授予「安装未知应用」，授权后再点一次即可。

## 七、常见问题

**Q：短信渠道报错「短信发送失败：xxx（getGroupIdLevel1）」？**
A：华为 / 荣耀 / 鸿蒙机型缺少**「电话」权限**。去
`设置 → 应用 → 应用管理 → 短信转发 → 权限 → 电话` 设为允许即可。
本应用已内置该权限的申请，重新安装后在首页点「授予短信权限」会一并申请。
根因：这些 ROM 的 `SmsManager` 内部调用了需要 `READ_PHONE_STATE` 的 `getGroupIdLevel1()`。

**Q：发件号码 / 关键词设成白名单后，所有短信都不转发了？**
A：打开「最近记录」，看那条「已过滤」的说明 —— 现在它会写出**实际比对的值**和**当前生效的规则**：

- 显示 `白名单里没有任何规则（可能填了但没点「保存」）`
  → 规则没存进去。回设置页重新填，并点一下「保存」。
- 显示 `发件号码「xxx」不在白名单内；当前白名单：yyy`
  → 把 xxx 和 yyy 逐字对一下。多半是短信的实际发件号码与你以为的不同
  （例如规则没写全、号段有多个子号）。

匹配规则再强调一次：号码是**「包含」**匹配。
规则写 `106` 能命中 `10658216`；规则写 `10658216` **不会**命中 `10658217`。
所以 106 号段建议用前缀（如 `106`）或 `re:^106`。

另外，设置页现在会在你**直接按返回键**时提示「有未保存的修改」，不会再让改动静默丢失。

**Q：普通短信能转发，但验证码短信转发不了？**
A：几乎可以确定是系统短信 App 的「**验证码安全保护**」和「**通知信息整合**」开着。
这两个开关会让系统**不把含验证码 / 通知类的短信广播给第三方应用** ——
我们连收都收不到，所以「最近记录」里一片空白，**这不是过滤规则的问题**。

关闭方法：打开系统「信息 / 短信」App → 右上角「⋮」→ 设置 → 关闭
**验证码安全保护** 与 **通知信息整合**。

App 的「设置 → 权限检查」里也列了这一项，点「去检查」会尽量直接跳到那个页面。

**Q：测试消息能收到，但真实短信不转发？**
A：说明 Webhook 配置正确，问题在收短信环节。依次检查：
① 短信权限是否授予；② 应用启动管理是否放开（见第五节）；③ 转发开关是否打开；
④ 是否被过滤规则拦下了（看「最近记录」里有没有「已过滤」）。

**Q：钉钉提示 `errcode=310000` 或 `sign not match`？**
A：加签密钥填错，或机器人安全设置与填写不一致。
用的是「加签」→ 必须填密钥；用的是「自定义关键词」→ 密钥留空且模板需含关键词；
用的是「IP 白名单」→ 手机 IP 不固定，建议改用加签。

**Q：日志显示「已转发到邮箱」，但收件箱里没收到？**
A：先看那条日志的说明文字里有没有 `⚠️ Ethereal 测试账号`。
有的话，说明你用的是「生成测试账号」拿到的 Ethereal 账号 —— 它是**假 SMTP 服务器**，
邮件被截留在 ethereal.email 网站上，**不会转发给收件人**，所以收件箱当然没有。
换成你自己的邮箱（例如 QQ 邮箱 + 授权码）就会真正投递。
若没有这条警告却仍收不到，去收件人邮箱的**垃圾邮件**目录找一下，并确认收件人地址没写错。

**Q：邮箱渠道报「认证失败 535」？**
A：国内邮箱几乎都要求用**授权码**而不是登录密码。QQ 邮箱去
`设置 → 账户 → POP3/SMTP服务` 生成授权码；163 邮箱去 `设置 → POP3/SMTP/IMAP` 开启并获取。
填登录密码一定会 535。

**Q：邮箱渠道连不上 / 超时？**
A：先确认端口与 SSL 勾选**是否配套**：465 要勾选「使用 SSL」，587 要取消勾选（走 STARTTLS）。
不匹配时分别表现为「TLS 握手失败」和「连接超时」。
开了二次验证的账号（如 Gmail）需要单独生成**应用专用密码**。

**Q：短信内容被截断了？**
A：长短信已自动合并。若群里内容不全，通常是机器人单条消息长度上限（企业微信文本约 2048 字节），
可精简模板后重试。

**Q：换手机 / 重装后要重新配置吗？**
A：需要。配置保存在本机 SharedPreferences 中，不上传任何服务器。
若开了系统「备份与恢复」，卸载重装可能自动带回配置。

**Q：会不会把我的短信传到别的地方？**
A：不会。App 只做一件事：把短信内容 POST 到你填写的那个 Webhook 地址。
没有埋点、没有统计、没有自建服务器，代码全部在本目录可查。建议不要使用来源不明的第三方 Webhook。

### 想加一个新渠道（如 Server酱、Bark、自建 HTTP 接口）？

1. 在 `channel/` 下新建 `XxxChannel.kt`，实现 `Channel` 接口：

```kotlin
object XxxChannel : Channel {
    override val id = "xxx"

    override suspend fun send(config: ChannelConfig, text: String, timeoutMs: Int): String {
        val payload = JSONObject().put("content", text)
        return Http.postJson(config.webhookUrl, payload.toString(), timeoutMs)
    }
}
```

2. 在 `channel/Channel.kt` 的 `Channels.of()` 里登记
3. 在 `Config.kt` 的 `ChannelType` 里加上 id、名称、URL 示例
4. 在 `activity_settings.xml` 的 `toggleChannel` 里加一个按钮，并在 `SettingsActivity.load()` 里映射
